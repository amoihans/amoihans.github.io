## 文档切割
### chunk结构
- vec 索引
- content 原文
- metadata 标签
### 切割策略
- 固定大小 + 重叠 句子截断 破环语义完整性
- 语义边界切割
 - 按段落 \n
 - 按分隔符
 - 对于HTML可以按标题结构
 - spacy或nltk可以识别句子结束

- 特殊内容专项处理
 - 代码 以类或函数单位切割
 - 表格 整块保留

- 父子切割
 - 同一内容存两份 小chunk用于聚焦检索 包含前后上下文的大chunk用于返回
 - 代价是存储翻倍 所以构建复杂 但质量高

- Contextual Retrieval 
 - 在embedding前先用llm看着整篇文档为每个chunk生成背景说明 背景和chunk加在一起embedding

- 句子窗口检索
 - 每个句子单独向量化
 - 检索时返回句子前后的N个句子

- 命题化切割
 - 用LLM吧句子提取为独立的事实命题 语义密度极高

## Embedding
自然语言 -> 固定长度浮点数 靠训练得到
文本的余弦相似度 cos 只看夹角 不看长短 向量模长受文本长短 表达强度影响

- OpenAI text-embedding 1536维 -> 256维
- bge-large-zh-v1.5 经典中文模型 1024维
- bge-m3 中英文混合 1024
- Qwen3-Embedding 多种维度

维度越高精度越好

### 算法
- 静态词向量 Word2Vec和Glove 一词一映射 上下文无关 处理不了多义词
- 上下文相关向量 BERT 能同时看到前后文 句子要拼在一起比较相似度 每条文档跑一次 检索太慢了
- SBERT BGE 句子级别对比学习Embedding 每个句子独立生成向量 为比较文本相似任务做了优化 精度低于cross-encoder

## 向量数据库
- ANN算法 近似最近邻搜索
- 主要是求相似度 多维 而关系型数据库只是一维

索引算法
- HNSW 分层导航小世界 召回率率最高的ANN之一
 - 多层图 最上层稀疏图导航
 - 顶层快速定位大方向
 - 中层 一层层缩小范围
 - 底层 精确匹配
 - 建索引时内存消耗大 不适合内存受限场景
 - 主流都用此算法
 - M 越大图越密 精度越高 每个节点认识多少邻居
 - ef 候选集大小 越大召回越准 延迟越高
- IVF 倒排文件索引
 - 相似的向量被分进同一个桶
 - 一个桶是一个聚类
 - 搜索时先查询相关的桶
 - 内存占用小 适合超大规模
 - 精度比HNSW低 需要调参 聚类数量nlist和桶数量nprobe
 - Milvus在超大规模场景会用IVF索引

### 核心能力
- metadata过滤 混合检索 先过滤再ANN
- 实时更新 不需要停服重建
- 有些支持关键词检索

### 选型
- Qdrant 中小规模 Rust Docker 分布式支持
- Chroma 小规模 本地内存 无分布式 原型验证
- Milvus 多种索引 分布式 超大规模 读写分离
 - 内存优化 标量量化（SQ8） float32->int8 内存降低
- pgvector 与pg结合

### 相似度计算
- `cosine`（余弦相似度）：适用于文本语义检索，**最常用**
- `l2`（欧氏距离）：适用于图像等数值特征
- `ip`（内积）：适用于已归一化的向量
