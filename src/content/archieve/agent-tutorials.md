## prompt
评估
```md
任务：{task}

当前输出：
{current_output}

请评估以上输出：
1. 有没有事实错误或逻辑问题？
2. 有没有遗漏重要内容？
3. 表达是否清晰准确？

如果输出已经足够好，回复「PASS」；
否则指出具体问题并给出改进建议。
```

改进
```md
原始任务：{task}
当前输出：{current_output}
评估意见：{reflection}

请根据评估意见改进输出：
```

循环调用 直至PASS

# 12.记忆压缩
## 常见模型上下文

- claude 200k
- sonnet opus可扩展到1M
## 压缩方法
- 滑动窗口 硬截断 只记得最近 限制对话轮数
- 摘要压缩 丢失细节
- 层级式摘要 最近的不变 次近的摘要 最远的最高压缩

# 8. 记忆机制
记忆机制分四层：
- 感知记忆（当前单次输入的原始内容 处理完就消失
- 短期记忆（context window 里的对话历史）message列表
- 长期记忆（存在外部数据库、语义检索召回）
- 实体记忆（结构化提取的关键事实）。

## 存什么
- 用户片偏好习惯
- 任务执行的关键决策和结论
- 外部知识 （产品文档、FAQ

## 怎么存
结构化的偏好字段用关系数据库精确查，非结构化的知识和历史用向量数据库语义检索，两者配合使用。

## 记忆框架
- Mem0
- Letta
- Core Memory
- Zep  Graphiti

## 记忆整合
- 去重
- 冲突消解 时间戳
- 抽象提炼

## 记忆模块配合
- 任务开始前先读记忆
- 任务执行中 用记忆 短期记忆messages全程工作 遇到专业知识 用长记忆检索
- 任务结束后 主动写记忆 新知识写回持久化存储

「读 -> 用 -> 写」三个阶段形成完整闭环：每次任务开始时把历史积累读进来，执行中靠短期记忆保持连贯，结束后把新知识写回去沉淀。Agent 用得越多，积累越厚，越来越「了解」用户
